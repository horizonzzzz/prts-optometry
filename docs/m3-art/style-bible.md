# M3 美术风格圣经（像素风横版平台跳跃）

M3 是明日方舟题材的像素风横版平台跳跃小游戏。本文件约束 AI 生图与后续手绘素材，目标是让不同来源、分开生成的素材（背景层、平台、道具、危险物、终点、角色）能拼进同一画面。当前程序绘制的舰桥是构图与配色基准，不是最终画风。

## 1. 像素规格

AI 模型画不出严格的像素画，所以流程是"生成 → 后处理成真像素"，本节数字是后处理的目标。

| 项 | 值 |
|---|---|
| 美术原生分辨率 | 384 × 216（16:9），1 美术像素 = 2 逻辑像素 |
| 游戏逻辑分辨率 | 768 × 432，16 px 逻辑网格（= 8 美术像素）|
| 导出 | 原生 1x 存档；运行时用最近邻放大，禁止平滑缩放 |
| 视角 | 横版侧视，平视略俯；平台顶面可见，侧面垂直 |
| 地平线 | 逻辑 y ≈ 284（美术 y ≈ 142）|
| 地面顶边 | 逻辑 y ≈ 400（美术 y ≈ 200）|
| 角色活动带 | 逻辑 y ≈ 336–400（美术 y ≈ 168–200），此区域背景必须低对比 |

像素规则：

- 无抗锯齿、无半透明边缘、无渐变平滑；天空渐变用 4–6 条色带加抖动（dither）过渡。
- 描边：前景素材（平台、道具、危险物、终点）用 1 美术像素的深色描边；背景层不描边，靠色块分层。
- 统一像素密度：同一画面内不得混用不同像素尺寸（不能出现"大像素"和"小像素"混杂）。
- 不追求写实透视。平台、甲板、栏杆保持水平或垂直，避免斜切结构让玩家误判落脚点。

## 2. 调色板

与 `src/m3/render/theme.ts` 的 `THEME` 保持一致。最终成品必须量化到下表颜色（可加每色 1–2 个明暗派生色，派生色登记在 `assets/ai/palette.gpl`）。

| 色值 | 名称 | 用途 |
|---|---|---|
| `#82CDDD` | 晴空蓝 | 天空顶部 |
| `#FFEDBB` | 暖奶油 | 天空近地平线 |
| `#FFF9E6` | 云白 | 云、平台顶面亮边 |
| `#FFDB80` | 日光金 | 太阳、光晕 |
| `#B7C9BB` | 远山灰绿 | 远景轮廓 |
| `#8DADA7` | 舰体灰绿 | 罗德岛舰体 |
| `#709595` | 舷窗 | 舰体窗户 |
| `#B17E58` | 钢棕 | 甲板主体 |
| `#805D49` | 阴影棕 | 接缝、投影、缆绳、前景描边 |
| `#FFDC91` | 受光边 | 可落脚面顶部高光 |
| `#E9B976` | 甲板沙金 | 甲板受光面 |
| `#FFC364` | 蜂蜜黄 | 悬吊平台、强调 |
| `#4ADE80` | 荧光绿 | 猫眼等极小面积点缀 |
| `#C6674E` | 警示赭红 | 危险物、围巾 |
| `#202A30` | 墨黑 | 猫咪剪影 |

规则：画面九成以上是暖色与中性色；荧光绿只做极小面积点缀。危险不能只靠红绿差异表达。

## 3. 光照

- 主光来自右上方，对应太阳位置约 `(571, 93)`。受光边朝上、朝右。
- 可落脚表面顶部 1 美术像素用 `#FFDC91` 提亮，下方 1–2 像素用 `#805D49` 压暗。
- 悬吊平台底面加 2 美术像素阴影，与背景拉开层次。
- 不使用暗角、强写实反差或霓虹光。

## 4. 素材分层与交付

素材全部分离生成，由 Phaser 在运行时合成。**禁止把平台、道具画进背景层。**

从后到前：

| 层 | 素材 | 尺寸（美术像素）| 透明 | 水平平铺 | 视差系数 |
|---|---|---|---|---|---|
| L0 天空 | `bg_sky` | 384 × 216 | 否 | 否（纵向渐变，可拉伸）| 0 |
| L1 云与太阳 | `bg_clouds`、`bg_sun` | 576 × 142 / 64 × 64 | 是 | clouds 是 | 0.05 |
| L2 远山 | `bg_far` | 576 × 142 | 是 | 是 | 0.15 |
| L3 舰体 | `bg_hull` | 576 × 142 | 是 | 是 | 0.35 |
| L4 甲板与平台 | `tiles_deck`、`tiles_platform` | 16 的倍数，见下 | 是 | 是 | 1（随关卡）|
| L5 道具 | `prop_*` | ≤ 128 × 128 | 是 | 否 | 1 |
| L6 危险物 | `hazard_*` | ≤ 64 × 64 | 是 | 否 | 1 |
| L7 终点 | `goal_*` | ≤ 96 × 128 | 是 | 否 | 1 |
| L8 角色 | `cat_sheet`，见 `character-cat.md` | 144 × 216（24 × 24 一格）| 是 | 否 | 1 |

- 视差层底边（L2、L3）要落在地平线 y ≈ 142 附近，其下由甲板层遮挡，背景层自身不画甲板。
- 可平铺素材：左右边缘循环，检查办法是把图并排复制一份看接缝。
- 平台 / 瓦片：8 × 8 美术像素为一格，输出横向条带（左端、中段、右端各一段，中段至少 2 种变体），接入时再切分。
- 体积预算：单层背景 ≤ 150 KB（PNG，调色板模式），单件道具 ≤ 20 KB。超限先降色再入库。

## 5. 分层与对比

- 背景亮度不得高于角色剪影。角色固定为 `#202A30`，任何背景下都要能一眼看清轮廓。
- 远景降低饱和度与对比；不要把高对比线条、密集铆钉或强光斑放进活动带（美术 y ≈ 168–200）。
- 可落脚面必须明显比背景暖、比背景亮，并有连续的顶部亮边。
- 危险物同时用形状、位置和颜色区分：三角尖刺、条纹、悬空货箱。转成灰度后仍要能辨认。

## 6. 材质（像素画写法）

- **甲板**：暖沙色钢板，横向板缝每 8 像素一条，少量铆钉和磨损；顶边受光，不铺满高对比纹理。
- **平台**：蜂蜜黄窄板（高 2 格）加细缆绳，明确悬空；与甲板用颜色和阴影区分。
- **舰体**：冷灰绿大块面，窗户成排但低对比；桅杆、天线、吊臂用 1 像素细线。
- **云**：奶油白，底部略暗，边缘受光；用块状轮廓，不描黑边。
- **道具**：橙棕货箱、警示带、缆绳、救生圈；形状简单，轮廓清楚。

## 7. 禁止项

- 图片内出现文字、数字、水印、UI、按钮、logo（罗德岛抽象标记除外）。
- 背景里出现角色或生物；角色、陷阱、道具都做独立素材。
- 官方立绘正脸或高还原角色；需要角色时只用剪影、背影、局部。
- 暗色终端风、霓虹、写实照片风、厚重 3D 渲染、渐变平滑的矢量风。
- 视差层左右不能拼接。
- 透明素材边缘出现白边、黑边或半透明像素。

## 8. 生成与后处理流程

1. 关卡布局完成后，截一张 768 × 432 的简化画面，标出平台、危险区和角色活动带。
2. 按 `prompts/` 里的模板填写 brief：公共风格块 `_common.txt` + 对应素材模板。网关支持 `--ref` 时附上截图，不支持就用文字描述构图。
3. 先出小尺寸草稿看构图，通过后再出成品。透明素材让模型用纯色底（见模板），生成后抠底。
4. **后处理（必做）**：最近邻缩到美术原生尺寸 → 量化到调色板（不允许新增色，抖动仅用有序抖动）→ 抠底并清除半透明像素 → 平铺素材做接缝检查。
5. 主代理直接读图检查，重点看轮廓、地平线、活动带对比、无文字、像素是否统一。
6. 成品放 `assets/ai/<场景>/`，草稿放 `assets/ai/_drafts/`（不进 Git），并在 `assets/ai/ATTRIBUTIONS.md` 登记。
7. 接入 Phaser 后，设 `pixelArt: true`、`roundPixels: true`，用 844 × 390 截图复查角色可读性和平台边缘。

## 9. 验收清单

通用：
- [ ] 尺寸、体积符合第 4 节预算
- [ ] 无文字、水印、UI、意外角色
- [ ] 无抗锯齿，无半透明像素，颜色全部在调色板内
- [ ] 像素密度统一

背景层：
- [ ] 地平线约在美术 y = 142，层内不含平台与道具
- [ ] 视差层左右并排无接缝
- [ ] 活动带低对比，猫的黑色剪影清楚

前景素材：
- [ ] 可落脚面有连续暖色亮边
- [ ] 平台条带左 / 中 / 右段拼接无缝
- [ ] 危险物在灰度下仍可辨认
- [ ] 透明边缘干净

## 10. 提示词模板

`prompts/` 下每个模板都由 `_common.txt`（公共风格 + 禁止项）加素材专用部分组成，方括号占位符按关卡替换后再传给 `--promptfiles`。

| 文件 | 素材 |
|---|---|
| `_common.txt` | 公共风格块与通用禁止项 |
| `bg-sky.txt` | L0 天空渐变 |
| `bg-far.txt` | L1–L2 云、远山 |
| `bg-hull.txt` | L3 罗德岛舰体剪影 |
| `platform-tiles.txt` | L4 甲板与悬吊平台条带 |
| `props-hazards.txt` | L5–L7 道具、危险物、终点 |
| `cat-model-sheet.txt` | L8 小猫角色模型表（先出，定稿形象）|
| `cat-actions.txt` | L8 小猫逐动作帧条（9 个动作块，见 `character-cat.md`）|

模板是起点，不是最终提示词。每个区域的实际构图、天气和道具以关卡设计为准。
